Token Refresh & Troubleshooting### How token refresh works- **Access tokens** expire after ~3600 seconds (1 hour)- The system uses the **refresh token** to automatically get a new access token every time- **Refresh tokens** do not expire unless:  - The user revokes access  - The token is unused for 6 months  - The Google Cloud project's OAuth consent screen is in "Testing" and the token is >7 days old### Common errors and fixes| Error | Cause | Fix ||-------|-------|-----|| `invalid_grant` | Refresh token expired or revoked | Re-authorize: run `node gmail-auth.js` or visit `/google_auth_url` || `invalid_client` | Wrong Client ID/Secret | Check credentials in Google Cloud Console ΓåÆ Credentials || `access_denied` | User not in test users list | Add `banfjax@gmail.com` as a test user in OAuth consent screen || `redirect_uri_mismatch` | Redirect URI not registered | Add the redirect URI in Google Cloud ΓåÆ Credentials ΓåÆ edit the OAuth client || `Token refresh failed` | Multiple possible causes | Try both credential sets (app + OAuth Playground) || `MODULE_NOT_FOUND: GoogleTokens` | Wix collection doesn't exist | Create the `GoogleTokens` collection in Wix CMS or use Secrets Manager |### Re-authorize from scratchIf tokens stop working:1. Go to **https://myaccount.google.com/permissions**2. Find `BANF Admin` ΓåÆ Click **Remove Access**3. Wait 1ΓÇô2 minutes4. Run `node gmail-auth.js` or use OAuth Playground (Method A above)5. This forces Google to issue a new refresh token with `prompt=consent`### Fallback: OAuth Playground credentialsThe system has built-in fallback to the Google OAuth Playground's own client credentials:- Client ID: `407408718192.apps.googleusercontent.com`- Client Secret: `kd-_2_AUosoGGTNYyMJiFL3j`If the app's own credentials fail, the code automatically tries these.
