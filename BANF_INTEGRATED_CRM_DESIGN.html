🎯 Vision & Objectives

Build a fully integrated CRM where every collection is linked — enabling end-to-end automation from event planning → invitations → RSVPs → attendance → expenses → reimbursement → budget tracking, with cross-entity insights and reporting.

📦 Collection Definitions & Links

👤 CRMMembers CORE

Master member record — every person in the system

Key Fields:
memberId (PK), familyId → FamilyGroups, email, firstName, lastName, displayName, phone, isActive, emailDeliverable, isCorporateEmail, membershipType, memberSince, isECMember, isBOTMember, emailOptIn, smsOptIn
→ FamilyGroups ← EviteRSVPs ← EventAttendance ← ReimbursementTickets ← AdminRoles ← Payments

👨‍👩‍👧‍👦 FamilyGroups CORE

Family unit — links adults + minors

familyId (PK), displayName, familyType (family/couple/individual), primaryAdultId → CRMMembers, secondaryAdultId → CRMMembers, membershipType, isActive
← CRMMembers (1:N) ← FamilyHistory

📅 EviteEvents EVENT HUB

Central event record — hub for all event-related data

eventId (PK), eventName, eventDate, eventTime, venue, venueAddress, highlights, culturalDetails, estimatedBudget, status, maxCapacity, ticketPrice, createdBy → CRMMembers
← EviteInvitations ← EviteRSVPs ← EventAttendance ← EventBudget ← EventCultural ← EventExpenses

📨 EviteInvitations EVENT

Per-recipient invitation tracking

_id (PK), eventId → EviteEvents, recipientEmail, recipientName, token, sentAt, status, deliveryStatus, openedAt
→ EviteEvents → CRMMembers (via email)

✅ EviteRSVPs EVENT

RSVP responses — attending/declined/maybe

_id (PK), eventId → EviteEvents, memberId → CRMMembers, email, rsvpStatus (attending/declined/maybe), adultCount, childCount, guestNames, dietaryNotes, respondedAt, source (form/email/manual)
→ EviteEvents → CRMMembers

📋 EventAttendance EVENT

Actual attendance at events (check-in)

_id (PK), eventId → EviteEvents, memberId → CRMMembers, checkedInAt, checkedInBy, adultCount, childCount, checkinMethod (manual/qr/auto)
→ EviteEvents → CRMMembers ← EviteRSVPs (compare)

💰 EventBudget FINANCE

Budget categories & allocations per event

_id (PK), eventId → EviteEvents, categoryName (venue/food/cultural/decor/misc), allocatedAmount, spentAmount, approvedBy → CRMMembers, notes, status
→ EviteEvents ← EventExpenses

🎭 EventCultural EVENT

Cultural program details — performances, schedule

_id (PK), eventId → EviteEvents, programName, performerNames, programType (dance/song/drama/other), startTime, duration, coordinatorId → CRMMembers, notes, order
→ EviteEvents → CRMMembers (coordinator)

🧾 EventExpenses FINANCE

Individual expense items for an event

_id (PK), eventId → EviteEvents, budgetCategoryId → EventBudget, description, amount, vendor, receiptUrl, submittedBy → CRMMembers, submittedAt, status, approvedBy → CRMMembers
→ EviteEvents → EventBudget ← ReimbursementTickets

💳 ReimbursementTickets FINANCE

Reimbursement requests — linked to expense + event

_id (PK), eventId → EviteEvents, expenseId → EventExpenses, requestedBy → CRMMembers, approvedBy → CRMMembers, amount, status (pending/approved/paid/denied), paymentMethod, paidAt, receiptUrl, notes
→ EviteEvents → EventExpenses → CRMMembers (requester) → CRMMembers (approver) ← FinancialLedger

📒 FinancialLedger FINANCE

Master ledger — every financial transaction

_id (PK), eventId → EviteEvents, reimbursementId → ReimbursementTickets, memberId → CRMMembers, type (income/expense/reimbursement), amount, description, paymentMethod, category, transactionDate, reference
→ EviteEvents → ReimbursementTickets → CRMMembers

🏢 CorporateRecipients COMMS

Business/corporate email addresses excluded from notifications

email (PK), name, domain, reason, autoReplyPreview, excludeFromEvents, excludeFromNewsletter, detectedAt, source
→ CRMMembers (via email)

🛡️ Safety & Non-Interruption Guarantees
ConcernGuarantee
RSVP form must stay live All CRM cleanup endpoints are separate functions from RSVP endpoints. They use different Wix Data queries and never modify EviteRSVPs, EviteEvents, or EviteInvitations status fields. The RSVP submit flow (post_evite_rsvp_submit) is completely independent.
Cleanup must not break invitations The crm_email_cleanup endpoint only modifies CRMMembers records (sets isActive=false). It does NOT delete records — only deactivates. The EviteInvitations records remain intact so historical data is preserved.
Corporate filter must not remove members The crm_corporate_filter endpoint creates NEW records in CorporateRecipients and only adds flags to existing CRMMembers records (isCorporateEmail=true). No deletions.
Existing collection schemas unchanged Only NEW fields are added to existing collections (e.g., emailDeliverable, isCorporateEmail). Existing fields and data are never modified by the cleanup process. Wix schemaless design makes adding fields safe.
Rollback capability All deactivations include timestamps and reasons in the notes field. A reactivateEmail utility can restore any deactivated member. Local agent state file tracks every action for audit.
