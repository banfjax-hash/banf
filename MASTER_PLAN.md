THE KEY TECHNICAL PROBLEM ΓÇö Wix Content-Type### 3.1 What's HappeningWix's HTTP functions on `.wixsite.com` subdomains **force `Content-Type: application/json`** on all responses, regardless of what your code sets. This means when a browser visits `banfwix.wixsite.com/banf1/_functions/home`, it sees `Content-Type: application/json` and displays the raw HTML text instead of rendering it.On custom domains (`www.jaxbengali.org`), Wix **respects** the `Content-Type: text/html` header set in the backend code. The pages render correctly there.### 3.2 Why This Happens| Domain Type | Content-Type | Why ||-------------|-------------|-----|| `*.wixsite.com` (preview) | Always `application/json` | Wix platform security policy for preview/dev URLs || Custom domain (`.org`, `.com`, etc.) | Respects your code's header | Production-mode CDN serving |This is a **platform limitation** ΓÇö cannot be fixed in code.### 3.3 Implication for Development- **DEV site** (`banfwix.wixsite.com/banf1`): HTML endpoints will always show raw text in browser. Use this site only for testing that the code deploys and backend functions work (via `/_functions/health`, JSON APIs, etc.).- **PROD site** (`www.jaxbengali.org`): HTML renders correctly. This is where everything needs to work end-to-end.> **Bottom line:** Don't worry if `banfwix.wixsite.com/banf1/_functions/home` shows raw HTML in browser ΓÇö that's normal. The test that matters is `www.jaxbengali.org/_functions/home`.---## 4.
